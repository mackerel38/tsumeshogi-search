# 持金と馬の位置を同時に要求する出口部品

盤上：攻方馬23、玉方玉11・歩22。攻方持金1枚。自玉なし。
使わない玉以外の駒はすべて玉方持駒。

| 入口 | 検証結果 |
|---|---|
| 馬23・持金1枚 | ▲12金打まで。全初手の1手詰を列挙し、この1通りだけ。攻方持駒を使い切る |
| 馬23・持金なし | 全王手を含む7局面・6辺の玉方戦略で不詰を独立検証 |
| 馬24・持金1枚 | 全王手を含む13局面・12辺の玉方戦略で不詰を独立検証 |

二つの不詰証明の玉方応手はすべて玉の移動・捕獲で、合駒を使わない。
python-shogiとcshogiで合法性、全攻方王手、遷移、終端を照合した。

これは条件付きの出口部品で、長編作品ではない。外側の機構が金を取得し、馬を所定位置へ戻し、この入口へ強制的に到達させる手順は未作成。別の駒を足した局面に、この不詰証明をそのまま適用しない。

009の初案にあった桂13を外しても条件が成立したため、010として保存した。桂の除去で別の1手詰出口もなくなった。盤上2枚へさらに減らす実験では、馬24・持金1枚の不詰証明が未完了なので、ここでは検証済みの3枚構成を採用する。最小駒数とは主張しない。

公開リポジトリのルートでの再現：

```sh
python scripts/verify_resource_gate.py candidates/components/gold-and-horse-resource-gate-minimized
```

検証に詰将棋エンジンは不要。`contract.json` は両出口条件、各SFENは対応する入口、`*-nomate.json` は閉じた防御戦略を保存する。
