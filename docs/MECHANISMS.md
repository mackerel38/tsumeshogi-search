# 手数を稼ぐ仕組みの設計

目標は新作の通常詰将棋で1525手を超えること。未達成。
1525手版ミクロコスモスの盤面・棋譜を探索種や改変元にしない。既存作から参照するのは、変換・送り・位置変換を階層化する考え方だけ。古い改変実験を本プロジェクトの候補へ輸入しない。

局面の状態は盤面、双方の持駒、手番に加え、反復判定用の履歴を含む。進捗を表す変数を明記し、王手の連続で一段だけ変える手順を作る。

| 仕組み | 一巡の変化 | 組合せに使う条件 | 現在の証拠 |
|---|---|---|---|
| 持駒の受け渡し・変換 | 歩数を1変える、または歩を別種の駒に替える | 必要数が揃うまで出口を閉じる。余剰持駒で早く詰ませられないこと | 自作Horse54の86手で盤面復元・玉方P−1/攻方P+1を検証。この選択経路は玉方持歩1枚から合法に進められることも検査済み。玉方の選んだ応手で成立する経路であり、強制や無駄合の適否は未証明 |
| 位置送り | と金・馬・龍等の位置を一段進める | 前段の変換を終えないと次段へ行けず、逆戻りが最善防御にならないこと | 独立の強制部品をこれから作る。既存の長い協力経路を証明と扱わない |
| 駒を取り直して位置を変換 | 香などを捕獲・打ち直しで別の列へ移す | 列の移動が次段の送りを許す鍵となり、直接移動や別の打場所で迂回できないこと | 入出力契約の段階。独立局面未作成 |
| 障害物の段階的解除 | 通路を塞ぐ歩等を一枚ずつ移動・消去する | 各解除で前の長い手順をもう一度必要とし、早い捕獲による短絡を防ぐこと | 入出力契約の段階。独立局面未作成 |

## 合成条件

単に二つの長い手順をつなぐと長さは足し算になる。掛け算にするには外側の進捗が一段進むごとに内側を初期位相へ戻し、内側の処理をやり直させる必要がある。

例えば状態 `(外側位置 i, 内側位相 j, 持駒資源 q)` に対し、内側の完了だけが `(i,j終端,q) → (i+1,j初期,q')` を許す形を目指す。合成時に部品を飛び越える王手、他の部品の駒を取る手、合駒で資源を補う手、異なる打場所を全て調べる。

各部品の記録項目：入口局面集合、出口局面集合、変化する変数、保存される駒・持駒、終了条件、各段階の必要手数、全攻方王手、全玉方応手、早詰、駒余り、反復、無駄合。適用範囲を一つの入口に限定した証明を別の入口へ流用しない。

## 探索の順序

1. 自玉なし・少数駒で、まず位置送りの一段を作る。自玉は必要な機能が説明できる場合だけ採用する。
2. 一段の出力が次の入力になるか検査し、段数が増えても迂回できない仕組みにする。
3. 持駒変換または位置変換を内側に接続し、外側の一段ごとに繰り返させる。
4. 全体の詰みの上限と下限を照合し、攻方最短・玉方最長で1525手を超えることを証明する。

Actionsの最初の探索対象は既存の自作少数駒部品の復元可能性。これは部品探索の補助であり、並列化だけで記録更新を証明するものではない。
